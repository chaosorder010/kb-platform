# 文档

本目录维护与代码紧邻的项目知识，并作为所有维护文档的总索引。

## 命名

- `docs/` 下的目录使用 kebab-case。
- `docs/` 下的 Markdown 文件使用 UPPER_SNAKE_CASE，`README.md` 是索引文件例外。
- 单个 Markdown 文件默认不超过 200 行和 10,000 个字符；超过限制时拆分为职责聚焦的文件。

## 索引规则

- 新增、重命名、拆分、移动或归档文档时，同时更新最近的 `README.md` 索引。
- 每个 docs 子目录的 `README.md` 都是该目录的本地目录，应列出重要文件和用途。
- 文档只保留索引、约定和无法从代码直接推导的项目知识；具体实现以代码为准。

## 目录说明

- `spec/`：产品行为、API 契约和面向用户的需求。
- `test/`：测试策略、回归用例和手工验证记录。
- `arch/`：架构决策、代码约定、模块边界、数据流和集成边界。
- `agents/`：Agent 探索代码库时使用的领域与工单约定。
- `plan/`：本地活动实现计划，默认被 Git 忽略。
- `archive/`：本地完成计划、临时报告和历史记录，默认被 Git 忽略。
