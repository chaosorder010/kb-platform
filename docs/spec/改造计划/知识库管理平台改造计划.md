# 知识库管理平台改造计划

需求与验收原文：[知识库管理平需求台第一版.md](./知识库管理平需求台第一版.md)（§2.9 全文 / 2.9.11）。本文件是实施 SSOT；字段级表结构与接口字段以需求 §2.9.7 / §2.9.8 为准，此处只写决策与落地增量。

## 目标与边界

- **目标**：按需求 §2.9.1–2.9.11 **全文交付**（页面、模块、规则、接口、流程、验收），打通「登录 → 导入知识单元 → 配权限 → 鉴权问答 → 看板/FAQ/缺口」完整演示；保留现有 RAG 主路径（LangGraph、BGE-M3 混合检索、HyDE、WebSearch、RRF/Rerank、SSE、`item_name` 确认、MinIO/Milvus/Mongo 客户端）。
- **知识单元（KU）**：1 个导入文件 = 1 个知识单元；Milvus chunk 经 `unit_id` 归属；数据权限配在知识单元上。
- **明确不做（需求未要求）**：SSO/LDAP、多租户、检索前权限预过滤。

## 技术决策

| 决策 | 选择 |
|------|------|
| 业务库 | MongoDB 全量；向量仍 Milvus |
| 服务形态 | 单进程 `knowledge/api/app_main.py` 挂载全部 `/api/*`；删除旧 `/upload` `/query` 双端口入口 |
| 前端 | 仓库根目录 `frontend/`：React + Vite + Ant Design；`knowledge/front/*.html` 在 React 可用后删除 |
| 登录态 | JWT access token + bcrypt；前端 localStorage；登录页 + 个人中心（身份/部门/角色） |
| 操作权限 | 细权限码（菜单 + 按钮：增删改查、AI 访问等）+ 角色权限树配置 + 前端动态菜单/按钮控制 |
| 数据权限 | 默认无权限；`global` / `department` / `role` / `user` OR；统一权限选择弹窗；种子为示例 KU 预配 |
| 鉴权插入点 | Rerank 之后、答案生成之前按 `unit_id` 过滤；保留 `item_name` 确认 |
| 无权限提示 | 仅用授权内容生成答案；独立「权限缺失」卡片 |
| 导入格式 | PDF、Markdown、Word、TXT；Word → 转 Markdown/文本后进入现有切分/向量管道 |
| 导入 UX | 拖拽/多文件/文件夹多选（目录能力用浏览器文件夹选择近似）；解析进度轮询 |
| KU 内容 | 列表筛选；编辑标题/正文/标签/附件（附件 MinIO）；状态机 + 每次保存写版本快照 |
| Milvus | 重建/新集合，`unit_id` 正式标量字段；示例可重导 |
| FAQ/缺口 | embedding 聚类语义去重挖掘；审核发布；向量相似阈值缓存命中；缺口聚类；已发布 FAQ 库；缺口一键创建关联 KU |
| 看板 | 指标卡 + 问题/单元 TOP + 日/周访问趋势 + Token/耗时走势与分布；数据来自 `qa_access_logs` |
| 组织页 | 用户（增改、重置密码、启停用）、角色（权限树）、部门树（负责人/成员） |

## 数据集合

需求 §2.9.7 集合（Mongo 文档模型）：`users`、`departments`、`roles`、`user_roles`、`role_permissions`、`knowledge_units`、`unit_permissions`、`qa_access_logs`、`faqs`、`knowledge_gaps`。

落地增量（需求未单列表、页面需要）：

- `knowledge_unit_versions`：`unit_id`、`version`、`content`、`editor_id`、`created_at`
- `knowledge_units` 增补：`tags`、`attachment_ids`、`status` 枚举（如 `draft` / `published` / `disabled`）
- 附件元数据（可嵌在 KU 或独立集合）：MinIO object key、文件名、大小、上传者

## 交付顺序

先竖切主链路，再补齐需求全文余量。

1. **文档与入口**：README 更名；`app_main.py` 骨架。
2. **Mongo 模型与种子**：上列集合；四账号 + 两部门 + 示例 KU 权限 + 角色权限树种子。
3. **认证与组织 API + 页**：JWT/bcrypt；用户/角色权限树/部门树；个人中心；动态菜单/按钮。
4. **知识单元与导入**：PDF/MD/Word/TXT；批量与进度；KU CRUD；标签/附件；状态+版本快照；Milvus `unit_id`；数据权限弹窗。
5. **鉴权问答**：登录 → FAQ 向量缓存 → 召回（含 item_name）→ Rerank 后鉴权 → 缺失卡片 → 写 `qa_access_logs`。
6. **前端并行**：自认证/组织 API 起同步铺页面；alice/bob 同问演示。
7. **业务看板**：指标卡、TOP 榜、日/周趋势、Token/耗时分布。
8. **FAQ / 缺口全文**：聚类挖掘、审核、已发布库、向量缓存、缺口列表与一键建 KU。
9. **交付物**：初始化/种子脚本、示例文档、`docs/api.md`、验收勾选；删除旧 HTML 入口。
